# HW-101-upload-rate-limit - 2026-07-08-1410

**Ticket:** [HW-101-upload-rate-limit](../../../projects/harborwatch/tickets/HW-101-upload-rate-limit.md)

## Did
- Read the July 2 / July 19 incident notes; confirmed both were single-client bursts
  (one API key, 40–60 req/s for ~2 min) — per-key limiting is the right shape, global
  limiting would punish innocents.
- Evaluated `rack-attack` vs a hand-rolled Redis sliding window. Recommended **hand-rolled**:
  rack-attack's throttle is fixed-window (burst at the boundary = 2x limit, which is
  exactly the failure mode from the incidents) and we already run Redis. ~60 lines.
- Implemented `app/middleware/rate_limiter.rb`: sliding window via a Redis sorted set per
  key (`ZADD` timestamp, `ZREMRANGEBYSCORE` prune, `ZCARD` count), returns 429 +
  `Retry-After` with seconds-until-oldest-entry-expires.
- Wired into `config/application.rb` middleware stack, `/api/v1/metrics` only.
- Started request specs: under-limit and at-limit cases written and passing.
