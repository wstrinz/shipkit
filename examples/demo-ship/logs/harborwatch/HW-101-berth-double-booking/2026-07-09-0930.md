## Learning candidate
**Race specs can't run inside the test suite's wrapping transaction.**
The transactional-fixture wrapper puts every writer in one shared transaction, so two
"concurrent" inserts never actually collide — the conflict under test can't fire, and the
spec hangs or falsely passes. Opting the spec out of the wrapper and giving each writer
its own real connection makes the race real *and* deterministic. Verified here (spec that
hung to timeout → 80ms, deterministic). Reusable for any DB-enforced invariant — the
resume-vs-poller race in HW-102 will hit this exact shape.
